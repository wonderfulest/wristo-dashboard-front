# Wristo Dashboard 全站移动端适配设计

## 目标

让 `wristo-dashboard` 的全部已登录后台页面在 375px、390px、768px 和桌面宽度下可用。移动端应能完成导航、查询、查看数据、分页和主要管理操作，同时保持桌面端现有信息密度与交互方式。

## 设计原则

- 复用现有 Vue 3、Element Plus、`useResponsive`、移动抽屉菜单和 `ResponsiveTableShell`。
- 以 768px 作为手机断点，1024px 作为平板及窄桌面断点。
- 不在移动端机械隐藏业务字段或管理操作。
- 高频列表采用移动卡片；依赖多列比较的复杂表格保留表格并允许横向滚动。
- 公共规则解决共性问题，页面级样式只处理该页面的特殊结构。
- 本次只调整布局和展示，不修改接口、权限与业务流程。

## 公共框架

### 顶部与导航

- 手机端隐藏桌面顶部导航和侧边栏，使用已有菜单按钮打开左侧抽屉。
- 抽屉展示完整菜单层级，自动展开当前路由所在分组，路由跳转后关闭。
- 顶部栏保持菜单按钮、Wristo 标识和用户入口；用户名超长时截断。
- 面包屑允许横向滚动或省略中间层级，不能撑破视口。

### 内容区域

- 手机端移除桌面卡片阴影和多余外边距，内容区使用 12px 内边距。
- 页面标题、说明、筛选区和操作区允许换行。
- 所有页面禁止产生由固定宽度容器导致的整页横向滚动；只有明确的表格滚动容器可以横向滚动。
- 页脚在手机端改为自然文档流，内容居中并允许换行。

## 页面内容模式

### 查询和操作区

- 手机端输入框、选择器、日期控件和主要按钮占满可用宽度。
- 筛选项改为单列；相关的两个短字段可使用两列网格。
- 主要动作放在筛选区之后，危险或低频动作保持可见但与主要动作分组。
- 按钮组允许换行，点击区域高度不低于 40px。

### 表格与列表

采用两种明确模式：

1. 高频业务列表使用卡片模式。适用于订单、用户、商品、退款、营销记录等需要在手机上频繁查看和操作的页面。卡片显示主标识、状态、2 至 6 个关键字段和完整操作入口，次要字段可折叠。
2. 复杂管理表格使用滚动模式。适用于字段数量大、需要列对比、配置矩阵或日志明细的页面。表格放入 `ResponsiveTableShell`，设置合理最小宽度并显示横向滚动；手机端取消固定列，避免遮挡内容。

分页在手机端换行并居中。空间不足时隐藏跳页和每页数量控件，保留总数、上一页、页码和下一页。

### 表单、弹窗与抽屉

- 表单标签置于控件上方，控件宽度为 100%。
- 弹窗宽度为视口减 24px，内容区限制最大高度并独立纵向滚动。
- 复杂编辑页面优先使用全宽抽屉或接近全屏的弹窗。
- 日期面板、级联选择器、上传区和富文本编辑器不得超过视口。
- 弹窗底部操作允许换行，主要提交按钮保持清晰。

### Dashboard 与图表

- 统计卡片在手机端单列，平板端按两列排列。
- 图表容器监听尺寸变化并自适应宽度。
- 图例、日期筛选和图表工具栏允许换行，避免覆盖绘图区。
- 数据表仍遵循卡片或滚动模式。

## 实施边界

实施按以下顺序展开：

1. 盘点路由与页面结构，建立移动端覆盖清单。
2. 修正公共框架、全局 Element Plus 规则和通用响应式组件。
3. 适配 Dashboard 首页及共享组件。
4. 按路由分组适配商品、订单、营销、商户、系统、运营及其他管理页面。
5. 收敛重复样式，补充响应式源代码契约测试。
6. 执行静态检查、单元测试、生产构建和浏览器视口验证。

不修改后端接口，不重做视觉品牌，不改变桌面信息架构，也不执行部署。

## 错误与兼容处理

- 页面接口失败时保持现有错误处理逻辑，响应式改动不得吞掉错误提示。
- 加载态和空状态必须在手机宽度下居中且不溢出。
- 桌面端既有固定列、工具栏和高密度布局保持不变。
- 对无法合理卡片化的页面，使用可预测的局部横向滚动作为降级方案。

## 验证标准

### 自动验证

- `npm run test:unit`
- `npm run build`
- `git diff --check`
- 响应式源代码契约测试覆盖公共断点、移动菜单、表格壳和关键页面模式。

### 浏览器验证

使用 375px、390px、768px 和桌面宽度检查：

- 登录后导航与菜单层级可用。
- 页面没有非预期的整页横向滚动。
- 筛选、分页、主要操作和弹窗可点击。
- 表格卡片或局部滚动符合页面模式。
- Dashboard 卡片和图表没有截断、重叠或溢出。

浏览器验证依赖可用的登录状态和运行环境；若无法访问，将与构建结果分开报告，不把静态检查视为浏览器验证。
